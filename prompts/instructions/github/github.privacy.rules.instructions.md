Generate or revise the `PRIVACY.md` data-handling document for this GitHub repository using the `github.privacy.template.instructions.md` template.

## Strict Template Fidelity Mode (Default)

Strict fidelity applies to every `PRIVACY.md` creation or revision and overrides conflicting instructions.

### Generation Contract

1. Use an exact copy of `github.privacy.template.instructions.md`; preserve every mandatory template section, subsection, table, bullet structure, heading order, punctuation, and whitespace layout.
2. Replace only `[[PLACEHOLDER]]` tokens. Apply language rules only to inserted values; never rephrase, normalise, correct, or improve fixed text.
3. Add only genuinely relevant sections that neither replace, rename, reorder, nor omit template content.
4. Resolve template-marked conditional blocks exactly as written; core sections and headings remain mandatory.
5. Ensure `README.md` contains an accurate Privacy section or link.

### Failure Behaviour

- Unknown required placeholder: cease generation and request one concise clarification. Never produce a partial data-handling document.
- Do not infer data practices, retention periods, external processors, or user controls from repository metadata alone.

### Mandatory Validation Before Final Output

- Headings match the template exactly in text and order.
- No template-defined section is absent.
- Any added section or subsection is repository-relevant and purely additive.
- No fixed template line was rephrased.
- All resolvable placeholders were replaced.
- No unsupported claim is presented as an implemented practice.

If a `PRIVACY.md` previously exists, preserve accurate and current content, and revise only what has changed or is absent. If no `PRIVACY.md` exists, create one from the template.

Use the exact template wording for fixed sections. Do not reword, paraphrase, or alter mandatory headings or paragraphs; only replace placeholder tokens such as `[[Project or service name]]`, `[[Repository URL]]`, and `[[Privacy contact method]]`.

Fill in all `[[PLACEHOLDER]]` values from verified project evidence or maintainer instructions. Remove template comments and example rows from the final output. Do not claim that the project collects, shares, retains, secures, or deletes data unless that practice is verified.

## Conditional Content Rules

### Sections

Include these sections only when the specified conditions are met:

| Section | Condition | Notes |
|---------|-----------|-------|
| Table of Contents | Always include. | Include all `##`, `###`, and `####` headings in order. |
| Self-Hosted Deployments | Include when the project can be deployed and operated by users or organisations. | Distinguish the project maintainer's practices from each instance operator's responsibilities. |
| Data We Handle | Always include. | Distinguish data provided by users, collected automatically, generated by the application, and received from third parties. State when a category is not handled. |
| Processing and Use | Always include. | Map each verified processing activity to the relevant data category and application feature. |
| Storage, Retention, and Deletion | Always include. | Describe where data is stored and verified retention or deletion behaviour; do not invent a period. |
| External Processing and Integrations | Always include. | Name verified external services, recipients, or integrations and explain the data flow. |
| User Controls and Requests | Include when users or operators have documented controls or request procedures. | Describe the control or procedure without making unsupported legal claims. |
| International Transfers | Include when data may be transferred across countries or regions. | State the verified locations or identify the point requiring maintainer confirmation. |
| Children | Include when the service is directed to children or age restrictions apply. | State the verified age behaviour or omit unsupported thresholds. |
| Document Changes | Always include. | Explain how this technical description is kept current. |
| Contact | Always include. | Provide a verified maintainer or instance-operator contact. |

### Content Rules

- Describe actual data flows, not merely capabilities that are present in source code.
- For self-hosted deployments, distinguish data processed by the software from data transmitted to project maintainers or external services.
- State that the self-hosted instance operator controls local storage, logs, backups, access, retention, and applicable user requests unless the project actually controls those functions.
- Identify configuration-dependent data flows, telemetry, update checks, reverse proxies, object storage, email providers, and authentication services when verified.
- Use plain language and distinguish required data from optional data.
- State explicitly when a category of personal data is not handled or is not applicable.
- Minimise personal-data detail; never include secrets, credentials, private contact data, or unverified processor names.
- Describe user and operator controls as implemented behaviour, not as legal entitlements.
- Link to repository documentation and provider information using verified URLs.

### Always Include

- An introductory summary describing the document scope and information date.
- `## What This Document Covers` explaining the repository, application, or service to which the document applies.
- `## Self-Hosted Deployments` when self-hosting is supported.
- `## Data We Handle`.
- `## Processing and Use`.
- `## Storage, Retention, and Deletion`.
- `## External Processing and Integrations`.
- `## Document Changes`.
- `## Contact`.

## Styling & Format Rules

- Respect the instructions in `language.instructions.md` for all PRIVACY text, including spelling, phrasing, and language conventions.
- Use clear headings and concise, actionable statements.
- Remove all HTML comments from the final output.
- Always fill `[[PLACEHOLDER]]` values with verified project details; omit template comments and example rows.
- This is a technical description of application behaviour, not legal advice or a compliance certification.
