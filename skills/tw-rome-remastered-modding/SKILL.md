# Total War: Rome Remastered Modding

Apply when authoring or reviewing content for **Total War: ROME REMASTERED** (Feral Interactive, 2021; Steam app 885970), the remaster of Rome: Total War. The engine is the original Total War engine with the 2.0.x patches, so the RTW data model still applies, but the mod system, the scripting layer, the graphics pipeline, and most hard-coded limits were replaced.

Source material: the official [FeralInteractive/romeremastered](https://github.com/FeralInteractive/romeremastered) repository — `README.md`, `RomeRemasteredDifferences.md`, `RomeRemastered204.md`, `RomeRemastered204FileChanges.md`, `documentation/data_file_guides/` (`EDU`, `DMB`, `EDB`, `descr_campaigns`, `descr_sm_resources`, `descr_senate`, `descr_battle_ai_personalities`, `feral_descr_*`, `toggles`, `string_overrides`, `data_controlled_features`, `unit_capabilities`, `building_capabilities`, `traits_and_ancillaries`), `documentation/feature_guides/` (`Scripting`, `Scripts_commands`, `Scripts_conditions`, `Scripts_events`, `logging`, `ui_modding_guide`, `ui_modding_example`, `image_formats`, `Battle_and_Campaign_Formulae`, `Campaign_Map_Pathfinding`, `AI_Diplomacy`, `Senate_Offices`, `hording`, `movie_cam`, `MiscellaneousTips`), `documentation/techart_guides/`, and `example_mods/`; plus the [TWC Wiki](https://wiki.twcenter.net/index.php?title=Total_War:_Rome_Remastered_-_Modding) pages `Total War: Rome Remastered - Modding`, `File Differences - Rome Remastered`, `Porting a Mod to Rome Remastered`, `Creating New Campaign Map in Rome Remastered`, `Unit Models in Rome Remastered`, and `Rome:Total War & Remastered - Modding Index`. That wiki sits behind a bot challenge, so read it through a browser or an archive snapshot. Documentation tracks 2.0.4; treat any unconfirmed detail as needing verification against the installed `Contents/Resources/` files, the generated `docudemon_*.txt`, and the log files.

## Non-Negotiable Build Rules

1. **Never edit game files.** Work only inside the mod folder. Steam file verification and patches overwrite `Contents/Resources/`; copy a vanilla file into the mod before changing it.
2. **A mod is a folder with `data/`, `modinfo.json`, and `filelist.json`.** Live folders are `%LOCALAPPDATA%\Feral Interactive\Total War ROME REMASTERED\Mods\Local Mods\<Mod Name>\` and `...\Mods\My Mods\<Mod Name>\`. Workshop subscriptions land in `steamapps/workshop/content/885970/<id>`.
3. **The manifest is the build output.** `filelist.json` is generated by **Regenerate Manifest** in the Feral launcher. A stale or missing manifest means new files are never loaded, and a missing manifest at all silently boots the vanilla game.
4. **Overriding is whole-file replacement by relative path.** A file at `<mod>/data/world/maps/campaign/imperial_campaign/descr_strat.txt` replaces that file; there is no merge, no patch syntax, and no per-line override. Copy the vanilla file, then edit the copy.
5. **Keep every path short.** A blank launch error with a yellow `!` is usually total path length, not content. Short mod-folder names, no `copy (2)` duplicates, no leftover long-named backups.
6. **Declare the supported base games and match their internal names.** `Supports Rome` / `Supports BI` / `Supports Alex` gate the mod to a base campaign. Faction, culture, religion, unit and region names must match the data set the mod is played on, or every file that mentions them must ship.
7. **Regenerate after adding, renaming, or deleting any file**, and never leave a 0 KB file in the mod — an empty `descr_events.txt` or `descr_disasters.txt` breaks the manifest; leave a comment line instead.
8. **Campaign scripting is opt-in per campaign.** The script filename goes at the bottom of `descr_strat.txt`, the script file sits in the campaign folder, and the game re-runs it on save reload.
9. **Indent with tabs, comment with `;` in data files and `;;` in script.** The data parsers are line- and brace-structured, not tolerant; a missing brace usually produces a silent no-op rather than a clear error.
10. **Save data text files as ANSI, not UTF-8.** The parsers are byte-oriented; a UTF-8 BOM or multi-byte character corrupts the first key. Verify by reopening the file in the editor before testing.
11. **A `.tga` reference usually means `.tga.dds` on disk.** The engine prefers `.tga.dds` over `.tga` when loading strat-map and unit textures, so keep the conventional name.
12. **Read the logs, do not infer.** `enable_logging`, `verbose_script_logging`, and `enable_dialogs` are launch options that turn silent failures into line-numbered messages. `-show_err` alone is the weakest of the four.

## Layout

```
Mods/{Local Mods|My Mods}/
  My Mod/
    modinfo.json                     # name, description, base-game support, tags, Workshop ID
    filelist.json                    # generated manifest: [{filename, checksum}, ...]
    data/                            # mirrors Contents/Resources/Data
      export_descr_unit.txt          # EDU: unit statistics
      export_descr_buildings.txt     # EDB: building trees, capabilities, recruitment
      export_descr_character_traits.txt
      export_descr_ancillaries.txt
      descr_model_battle.txt         # DMB: skeletons, models, textures, PBR
      descr_mount.txt                # mounts
      descr_model_strat.txt          # campaign-map character models
      descr_sm_factions.txt          # factions, cultures, religion, colours
      descr_sm_resources.txt         # resources and hidden resources
      descr_sm_major_events.txt      # moddable major events (Marian reforms, ...)
      descr_senate.txt               # super factions, offices, missions
      descr_cultures.txt             # culture UI and agent settings
      descr_character.txt            # agent types, incl. merchant
      descr_animals.txt              # handler animals
      descr_campaigns.txt            # campaign list, loyalty/religion toggles
      descr_unit_variation.txt       # ethnicity variation blocks
      descr_names.txt                # non-localised names, per faction
      descr_sounds.txt               # legacy index into sounds/descrs
      descr_strat_sundries.txt       # strat-map UI strings
      data_controlled_features.json  # feature switches (FOW, night, public order)
      data_controlled_variables.json # tunables used by the above
      toggles/                       # classic vs remastered feature switches
        toggle button states.txt
        classic/  remastered/
      original_overrides/            # files applied when the "original" option is on
      string_overrides/              # en.strings, de.strings, ... Feral UI overrides
      ui_overrides/                  # campaign and battle .pos layouts
      text/                          # export_units, export_buildings, expanded_bi, ...
      world/maps/base/               # functional map: map_*.tga, descr_regions, map.rwm
      world/maps/campaign/<campaign>/ # descr_strat, descr_win_conditions, mercenaries, events
      terrain/campaign/<campaign>/   # 3D mesh, heightmap/*.bin, descr_map_tiles.txt
      characters/  models_*/         # .cas models and PBR/texture sets
```

Workshop publishing uploads the folder as-is; the launcher embeds the manifest and `modinfo.json` metadata.

## Working Method

1. **Set up the mod skeleton and manifest first.** Create `data/`, `modinfo.json`, and an empty manifest, then add files one domain at a time and regenerate the manifest after each batch. A mod that shows no change almost always has a stale manifest, not broken data.
2. **Copy, then edit, the vanilla file.** There is no override granularity below "whole file", so identify the single vanilla file that owns the definition and replace it wholesale. Never ship a partial file expecting the game to merge the remainder.
3. **Confirm the base game and internal identifiers.** Check whether the definitions you are touching come from Rome, Barbarian Invasion, or Alexander; a BI mod inheriting Rome faction names fails at load.
4. **Register every reference before testing.** A unit exists only when the EDU `type` has a DMB model, a texture, an `export_units` name and description, a unit card, and an EDB `recruit` line. A resource exists only when `descr_sm_resources.txt` defines it and `descr_regions.txt` places it. A building capability must appear in the supported capability list.
5. **Script through `descr_strat.txt`.** Add the script filename at the bottom of the campaign's `descr_strat.txt`, put the file in the same campaign folder, and structure it as `script` / monitors / `end_script`. Use `declare_persistent_counter` for anything that must survive a save.
6. **Only use commands, conditions, and events that the current build advertises.** The game regenerates `docudemon_commands.txt`, `docudemon_conditions.txt`, `docudemon_events.txt`, and `docudemon_romeshell.txt` into `VFS/Local/Rome/documentation` on every launch; the shipped Markdown lists are only the delta notes.
7. **Verify in game, then read the log.** Launch with `enable_logging` (plus `verbose_script_logging` for scripts and `enable_dialogs` for pop-ups), reproduce the change, and read `VFS/Local/Rome/logs/message_log.txt`, `scripting_log.txt`, and `campaign_ai_log.txt`. A silently inert definition is a wrong filename, a stale manifest, a wrong scope, or a name mismatch.
8. **For a new or reshaped map, build the 3D layer separately.** The functional map comes from the `map_*.tga` and text files; the visible campaign map comes from the campaign `.cas` mesh, its textures, and its heightmap `.bin` files. Changing the TGAs alone leaves the old mesh on screen.

## Honest Limits

- The campaign mesh, heightmap bins, coastline, river mesh, and 3D frame are authored assets, not generated output: changing `map_regions.tga` does not reshape them. A functional map larger than the mesh produces sea, and an excessive mismatch can cause an error-less crash on load.
- Rivers and region borders cannot be made to align exactly; the border follows `map_features.tga` bends while the river model is fixed in `river_mesh.cas`. Editing `descr_aerial_map_tile_models.txt` to force straight river sections only reduces the anomaly.
- `map_trade_routes.tga` is vestigial: the flag is written and shown but no pathfinding or AI logic consumes it. `map_roughness.tga` is required but unused. `water_surface.tga` is unused in Remastered.
- A 20,000-face polygon limit per model persisted; unit scale tops out at Extreme (300 soldiers). Officers cap at 9. Levels per building tree and points per trait trigger remain constrained (9 levels, 100 points per trigger, 600 per threshold), and the official tables disagree on whether 2.0.4 lifted the level cap — verify against the shipped file.
- Buildings display across five settlement levels; adding a sixth works but breaks the building-browser visuals.
- `descr_animations`-style behaviour and the wave motion of the coastline are hard-coded; only the surf texture and model list are data.
- Several legacy files in `data/` are dead weight and are ignored by the engine (`descr_skeleton.txt`, `descr_grass.txt`, `descr_skydome.txt`, `descr_projectile.txt`, `descr_sm_settlements.txt`, and others); a mod that edits them changes nothing. The full obsolete list is in `references/mod-packaging.md`.
- `descr_items.txt` and `descr_vegetation.txt` are ignored when their `.db` counterparts exist, so regenerate the `.db` or ship neither.
- Battle AI difficulty logic, diplomacy intent, and most button behaviour remain in code; only the exposed constants, personalities, and reputations are data.
- Wiki coverage is uneven and partly stale: `File Differences` predates 2.0.2 and admits it. When the wiki is silent, read the shipped files, the 2.0.3→2.0.4 change list, and the `docudemon_*` output rather than guessing.
